# 2026-11-16

## Docker 镜像优化（VuePress 博客仓库 E:/neverland）

目标：优化镜像生成、缩小体积。改动文件仅 3 个：`.dockerignore`、`Dockerfile`、`nginx.conf`。

### 根因与优化点
- **构建上下文 272.78MB（56s 传输）**：`.dockerignore` 原未忽略 `.git`（210MB）。
  补齐忽略 `.git`/开发配置/`node_modules`/dist/缓存/文档后，上下文降到 ~23KB，增量构建 11s 全缓存命中。
- **分层缓存缺失**：原 `COPY . /neverland` 一锅端，改源码就重装依赖。
  改为先 COPY `package.json/pnpm-lock.yaml/pnpm-workspace.yaml` → `pnpm install --frozen-lockfile` → 再 COPY src。
- **pnpm store 进镜像层**：用 `RUN --mount=type=cache,target=/root/.local/share/pnpm/store` 缓存，不写层。
- **固定版本**：`npm install -g pnpm@12.18.0`（与 lockfile 一致）；registry 改为 `ARG NPM_REGISTRY`。
  ⚠️ 默认必须是官方源 `registry.npmjs.org`：**阿里源的 tarball CDN(cdn.npmmirror.com) 在 Docker 容器默认网络下超时**，
  `npm install -g pnpm` 直接 ETIMEDOUT（发布失败根因，详见下节）。曾误设为阿里源导致 release.bat 发布失败。
- **gzip 预压缩**：构建后把 JS/CSS/SVG/XML/TXT/webmanifest 用 `gzip -9` 压缩（删原件），
  nginx 配置 `gzip_static always` + `gunzip on`：支持 gzip 直接返回 .gz，不支持的 nginx 自动解压。

### 关键坑（务必记住）
- **不能压缩 .html**：nginx 目录首页 `index /index.html` 依赖真实文件，全压成 .gz 后访问 `/` 返回 403。
  保留 441 个 .html 不压，只压 579 个资源文件。
- **基础镜像残留 index.html**：`nginx:alpine-slim` 自带欢迎页 index.html(896B)，若被留下，
  非 gzip 客户端会拿到 "Welcome to nginx!"。生产阶段先 `RUN rm -rf /usr/share/nginx/html/*` 再 COPY dist。
- `COPY certs ./` 只拷目录**内容**不拷目录本身 → `/neverland/certs` not found；要 `COPY certs ./certs`。
- `# syntax=docker/dockerfile:1` 会触发从 Docker Hub 拉 frontend 镜像，受限网络下构建直接失败；Docker 29.x 内置支持 cache mount，去掉即可。
- 生产阶段配置/证书 COPY 放在 build 之后，避免仅改 nginx 配置就触发整站重建。

### 实测结果
- 上下文：272.78MB → ~23KB；增量构建 11s（全层 CACHED）。
- 最终镜像：约 70MB（理论：nginx 21MB + dist 48MB）→ **58.7MB**；dist 48MB → 28.9MB。
- 功能验证（curl -k 实测 443）：首页 + JS 在支持/不支持 gzip 两种客户端下均 200、内容正确。

### 环境注意
- 本机沙箱代理 `127.0.0.1:62149` 会拦 `cdn.npmmirror.com`（registry 通但 tarball CDN 超时）。
  实测**默认容器网络 + 官方源装 pnpm OK，阿里源直接卡死超时** —— 与代理无关，是 Docker 网络到该 CDN 不通。

## 发布失败复现与修复（同日续）
- 用户反馈发布失败，授权执行 `release.bat` 复现。复现到 3 个问题：
  1. **build 失败**：默认源是阿里源，`npm install -g pnpm@12.18.0` 拉 `cdn.npmmirror.com` 超时 ETIMEDOUT。
  2. **tag 源镜像名错**：`docker build -t neverland/blog` 但脚本写 `docker tag blog ...` → `No such image: blog:latest`。
  3. **假成功**：脚本只 echo 不检查 errorlevel，build/tag 都失败了仍继续，最终 EXIT 0 掩盖失败。
- 修复：
  - Dockerfile：`ARG NPM_REGISTRY` 默认值改回官方源 `https://registry.npmjs.org`。
  - release.bat：重写为 `LOCAL_TAG=neverland/blog` / `REMOTE_TAG=docker.ilyl.life:8443/neverland/blog` 变量化，
    每步 `if errorlevel 1 goto :fail` 失败即停，`:fail` 分支 exit /b 1。
- 重跑 `cmd //c release.bat` **全程成功**：build(442页) → tag → push 到 `docker.ilyl.life:8443/neverland/blog:latest`
  digest `sha256:819d8b719c3d2ce3d1ba03c4e8a91928ce311496931272e670283dda926fbf0e`，EXIT 0。
- 注意：pnpm 12 切官方源后 `pnpm install` 因 supply-chain 策略逐条校验 1230 依赖耗时 7m36s（单条 typescript 请求 36s），
  是构建变慢主因。

## 关闭 supply-chain 校验提速（同日续，用户要求）
- 开关：`pnpm install --trust-lockfile`（pnpm v12.15.0+，跳过 lockfile 的 supply-chain 校验 pass）。
  也可配 `trustLockfile: true`（pnpm-workspace.yaml），但会影响本地开发，故只用 CLI 参数、仅构建环境跳过，本地仍完整校验。
- 安全性：lockfile 已提交仓库 + `--frozen-lockfile` 不改写，构建环境视为可信；若外部协作者可改 lockfile 则不要跳过。
- Dockerfile 第 25 行 install 改为 `pnpm install --frozen-lockfile --trust-lockfile`。
- 实测（同官方源、默认网络）：`pnpm install` **7m46s → 2m5s**，整体 build ~11min → **3m37s**；
  "Verifying lockfile against supply-chain policies" 日志消失。产物完整：441 HTML + 579 .gz + 首页 + 证书，镜像 58.7MB 不变。
- 用 `docker build -t neverland/blog:speedtest` 验证后已删除测试镜像；未重新 push（当前线上 latest 是上一版镜像，功能等价，仅构建速度不同）。
